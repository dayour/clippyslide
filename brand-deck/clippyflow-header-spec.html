SECTION 01the header, labelled

Anatomy of the header

Two stacked rows. The titlebar carries identity + navigation; the taskbar carries action + state. Read it left-to-right, by cluster:

1 · BrandGlyph + wordmark or traffic dots. Window identity.
2 · TabsOpen surfaces. Active = nitrous underline.
3 · ToolsVerb launchers — terminal, browser, files, search.
4 · AgentsLive status. Spectrum dots carry meaning.
5 · AppsPinned nouns. Nitrous tick = running.
6 · ControlsReadout + theme, settings, profile, alerts.

SECTION 03the one rule that governs everything

Nitrous = structure · Spectrum = meaning

NITROUS 214° — structure only
›Active-tab underline — the only lit tab.
›Cluster rails — 1px dividers in the taskbar.
›Focus rings & hover outlines on every control.
›App "running" tick. Never a fill, never a status.
SPECTRUM — meaning only
RUN THINK IDLE ERROR
›Agent & app status dots use the five logo hues.
›App identity tints distinguish pins.
›Notification badge = magenta (needs attention).
›One lit element per cluster — the rest read dim.

SECTION 04interaction model

States, focus & keys

structure states (nitrous)
›:hover — nitrous wash or rim halo.
›:focus-visible — 2px nitrous ring, 2px offset.
›.active — nitrous inset/underline. One per cluster.
keyboard
⌘/Ctrl + Tnew tab
⌘/Ctrl + 1–9jump to tab
⌘/Ctrl + Ksearch / palette
Tab / ⇧Tabwalk clusters L→R

One-lit-per-cluster is the discipline that keeps a busy header calm: at any moment a single tab, a single tool, and a single readout state carry the eye.

SHIP ITrules + file map

Do / Don't

DO
✓Use nitrous for the active-tab underline, rails & focus.
✓Use spectrum for agent/app status & identity.
✓Keep one lit element per cluster.
DON'T
✗Fill a tab or tool with nitrous — it's structure only.
✗Use a status hue as decoration.
✗Light up two active tabs at once.
